# SCHEME_FORMAT.md — формат scheme.json

Читай при: правке json руками, спорах о валидации, миграциях, `put`/`sync`.

## Структура

```json
{
  "format": "block-llm",
  "version": 1,
  "rev": 12,
  "name": "Auth Flow",
  "project": { "root": ".", "codePaths": ["src/"] },
  "nodes": [
    { "id": "n1", "shape": "rect", "label": "Open app",
      "description": "скрытое описание для LLM/человека",
      "x": 120, "y": 80,
      "refs": ["src/auth/login.ts"] },
    { "id": "n2", "shape": "table", "label": "Catalog",
      "x": 320, "y": 80,
      "table": { "cols": ["name", "kind"], "rows": [["in", "file"], ["out", "file"]] } }
  ],
  "edges": [
    { "id": "e1", "from": "n1", "to": "n2", "style": "solid", "label": "next" }
  ],
  "meta": {
    "updatedAt": "ISO-время пишущего",
    "generator": "agent | human-editor | human-json",
    "nextId": { "n": 3, "e": 2 },
    "editor": { "rev": 12, "savedAt": "..." }
  }
}
```

## Правила

- `shape`: `circle | diamond | square | rect | table`; edge `style`: `solid | dashed`.
- `label` может содержать `\n` — элемент визуально растягивается вниз
  (в mermaid-экспорте переводы строк становятся `<br/>`).
- `table` (только для shape `table`): `cols` — заголовки колонок (макс 10),
  `rows` — строки данных (макс 50, ячейки — строки; недостающие ячейки
  рендерятся пустыми). На не-table ноде данные table игнорируются (warning).
- `description` — только у nodes; у edges — только `label`.
- Координаты — единственный источник геометрии. Никаких order у edges и
  waypoints: путь стрелки считается автоматически (orthogonal elbow).
- Авто-размещение: детерминированный BFS от корня (нода без входящих, иначе
  минимальный id). Сетка фиксирована: GRID_X=160, GRID_Y=100. Один граф →
  одна раскладка всегда (нужно для снапшотов и diff'ов). Ноды с явными x/y
  не трогаются, их ячейки пропускаются.
- `refs` опциональны — связь ноды с файлами проекта. `validate` проверяет
  существование путей → warning «ref протух». Это главный сигнал
  синхронизации схемы с кодом.
- Водяной знак `meta.nextId`: освобождённые id НЕ переиспользуются
  (n1 удалён → новый узел станет n3, не n1). Нарушение ломает diff/history.

## Валидация

error (запись ЗАПРЕЩЕНА): битые `from`/`to`, дубликаты id, неизвестный
shape/style, `version` > поддерживаемой, нечисловые x/y, format != block-llm.

warn (запись разрешена): сирота без связей, несуществующий ref, пустой label.

## Запись

- Атомарно: tmp + rename в той же директории.
- `rev` +1 при каждой записи; инкремент живёт в ядре (CLI и браузер одинаковы).
- CAS: `--rev N` = ожидаемая ревизия на диске; иначе отказ «scheme changed on
  disk … re-read with get and retry». Без `--rev` команда берёт актуальный rev
  сама (кроме `put`, где payload.rev всегда устарел — берётся с диска).
- Приоритет синхронизации — ТОЛЬКО rev. `updatedAt` для сравнения не используется.
- Любая успешная запись перегенерирует SCHEME.md и scheme.html (делает ядро).
- Неизвестные поля json СОХРАНЯЮТСЯ при записи (forward-compat).

## Миграции

- `version` в scheme.json — версия ФОРМАТА. `upgrade` проверяет совместимость;
  `version` больше поддерживаемой → error «обновите скилл», не молчаливая порча.
- Обновление скилла данные проекта не трогает: код живёт в скилле, в проекте
  только scheme.json/md/html/cache.
