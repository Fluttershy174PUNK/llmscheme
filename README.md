# 🗺️ llmscheme

**Живая схема твоего проекта.** Модули, потоки данных, экраны — всё в одном
JSON, который обновляется при каждом изменении кода и читается одинаково
человеком, AI-агентом и визуальным редактором.

---

## 🤔 Зачем это?

Когда проект маленький, он помещается в голове. Когда большой — нет. Тогда
объяснить ИИ, «что нужно поменять», проще всего **на схеме**: показал блок и
стрелку — и каждый понимает, о чём речь, без тысячи слов.

| Было | Стало |
|---|---|
| 🤷 «Как это устроено?» → grep + угадывание | ✅ открыл схему — видно модули и потоки |
| 📝 Рукописные доки, устаревшие вчера | ✅ `SCHEME.md` генерится из схемы |
| 💬 Долгое объяснение ИИ на словах | ✅ показал блоки на схеме — понятно сразу |
| 🧩 Несколько источников правды | ✅ один `scheme.json` — источник истины |

**Суть:** схема — это способ *договориться* о структуре проекта. Человек правит
её мышкой в визуальном редакторе, ИИ читает тот же файл и вносит изменения в
код — или наоборот.

---

## 🔄 Как это работает

```
                 ┌──────────────────┐
                 │   scheme.json    │  ← единый источник истины
                 │  (модули, рёбра) │
                 └────────┬─────────┘
                          │  при каждом сохранении
           ┌──────────────┼───────────────┐
           ▼              ▼               ▼
       SCHEME.md      scheme.html      REST / MCP
       (для чтения)   (визуальный      (для агента
        и grep)        редактор)        и скриптов)
```

**Схема** — это список **узлов** (модули, файлы, экраны, таблицы — что угодно)
и **рёбер** (как между ними текут данные или вызовы). Плюс **зоны** — пунктирные
группировки (слои, подсистемы).

Из одного `scheme.json` при каждой записи автоматически пересоздаются:

- `SCHEME.md` — читаемая сводка (mermaid-диаграмма + таблицы), удобно для grep,
  code review и LLM;
- `scheme.html` — самодостаточный редактор: открыл двойным кликом и двигаешь
  блоки мышкой, без сервера и без установки.

Рабочий цикл: **изменил код → обнови схему → экспорты перегенерились сами.**
Или наоборот: **поправил схему в редакторе → агент увидел diff и изменил код.**

## 🧩 Схемы — какие угодно

Схема описывает **то, что нужно именно тебе**. Частые примеры:

| Тип | Что описывает |
|---|---|
| `logic` | модули + потоки данных (архитектура) |
| `code` | граф вызовов, классы, функции |
| `ui` | экраны, маршруты, компоненты |
| `db` | таблицы и связи |
| `api` | эндпоинты и вызовы |
| … | **любой смысл** по твоему запросу |

Схемы независимы — у каждой свой `scheme.json`, журнал и редактор. Агент не
создаёт их сам: **при первом обращении спрашивает, схему чего делать**, дальше
только обновляет то, что уже есть.

## 🚀 Установка скилла (для AI-агента)

Скилл уже собран и готов. Один шаг — скопировать папку в скиллы агента:

```bash
git clone <url-репозитория> llmscheme
cp -r llmscheme/SKILL/llmscheme ~/.claude/skills/llmscheme
```

| Агент | Папка скиллов |
|---|---|
| Claude Code | `~/.claude/skills/` |
| Cursor | `.cursor/skills/` |

Готово — у агента появилась команда `block`. Работает **офлайн**, без
`npm install`, без сети и API-ключа. Нужен только Node ≥ 22.18.

### Команды агента

```bash
node <skill-dir>/cli/block.ts init --type logic            # создать схему
node <skill-dir>/cli/block.ts node add --label "Login"     # добавить узел
node <skill-dir>/cli/block.ts edge add --from n1 --to n2   # связать узлы
node <skill-dir>/cli/block.ts validate                     # проверить
```

Агент читает схему до правок кода, а после — синхронизирует её с тем, что
изменилось. Полный ритуал и команды: [SKILL.md](SKILL/llmscheme/SKILL.md).

## 🖥️ Установка сервиса (веб-консоль + MCP для команды)

Когда над схемой работают несколько человек или нужен общий доступ:

```bash
cd SERVICE-MCP/llmscheme
cp .env.example .env          # задай ADMIN_PASSWORD
docker compose up -d
```

Консоль: `http://localhost:8080/` (логин `admin` / твой пароль).

### Что отдаёт сервис

| Что | Где | Для кого |
|---|---|---|
| 🖥 Веб-консоль | `/` | проекты, юзеры, API-ключи |
| ✏️ Редактор | `/editor/<схема>` | править схему в браузере |
| 📡 REST API | `/api/...` | скрипты и автоматизация |
| 🤖 MCP | `/mcp` | инструменты для AI-клиентов |
