# 🔐 Страница логина llmscheme-service

> Этот документ описывает `GET /` (страницу входа) сервиса
> [llmscheme-service-mcp](llmscheme-service-mcp/README.md): что на ней есть,
> как она устроена, как менять. Общая карта репозитория —
> [PROJECT.md](PROJECT.md).

## Что на странице

Единый пиксель-стиль всего проекта: шрифт **Press Start 2P** (base64-шрифты
latin+cyrillic извлекаются из editor-template при старте) и палитра PICO-8
(`--bg #1a1c2c`, `--panel #29366f`, `--accent #ffcd75`, `--err #ff004d`).

| элемент | где в схеме `📁 UI/page` | что делает |
|---|---|---|
| форма login/password | n3, n4 | `POST /api/login` → cookie `ls_token` → redirect `/admin` |
| `reset?` (n5) | n5 | раскрывает подсказку: как сменить пароль admin |
| pixel-кот (n2) | n2 | декор, SVG `shape-rendering=crispEdges` |
| readme-блок (n1) | n1 | краткое описание + ссылка на README репозитория |
| `ru/en` (n14) | n14 | переключение языка формы (подписи/подсказки/текст readme) |

Мобильная ширина (<640px): карточка складывается в одну колонку.

## Как работает вход

1. Браузер открывает `GET /` (или `/admin`) без токена → сервер отдаёт эту
   страницу со статусом **401** (браузер показывает HTML, скрипты получают
   JSON — по заголовку `Accept`).
2. Форма делает `POST /api/login` `{login, password}`.
3. Успех → сервер ставит **HttpOnly cookie** `ls_token` (SameSite=Lax,
   срок `TOKEN_TTL_DAYS`, по умолчанию 30 дней) и страница делает
   `location = /admin`.
4. Неудача → текст ошибки (`bad credentials`) в красной строке под кнопкой,
   страница остаётся на месте.
5. Далее cookie авторизует все страницы (`/admin`, `/editor/…`) сама; API
   из JS по-прежнему может ходить с `Authorization: Bearer`, MCP и скрипты —
   с `X-Api-Key: llm_…`.

## Смена пароля admin (подсказка reset)

Пароль admin задаётся **один раз** из `ADMIN_PASSWORD` при первом старте с
пустой папкой `data/` (создаётся запись в `lightdb.json`). Сменить:

```bash
cd llmscheme-service-mcp
# 1) остановить сервис
docker compose down
# 2) сменить пароль в .env
nano .env                       # ADMIN_PASSWORD=новый
# 3) удалить учётки (схемы в data/schemes сохраняются)
rm data/lightdb.json
# 4) запустить снова — admin пересоздастся с новым паролем
docker compose up -d
```

Пользователей, кроме admin, удаляет сам админ в консоли (`/admin` →
Администрирование → x у строки). Каждый юзер меняет... — смена пароля
обычного юзера через UI пока не реализована (см. PROJECT.md → «что дальше»).

## Где код и как менять

Весь код страницы — шаблон-строка `LOGIN_HTML` в
`llmscheme-service-mcp/server.mjs` (ищи `const LOGIN_HTML`). Там же:

- `CAT_SVG` — пиксельный кот;
- `FONT_CSS` — два `@font-face` блока, извлекаются из
  `llmscheme-skill/block_llm_core/editor-template.gen.html` при старте
  (поэтому **не** дублируй шрифты руками);
- объект `T` в `<script>` — все строки EN/RU.

Золотые правила:

1. **Стиль = стилю редактора**: новые элементы добавляй в той же палитре,
   кнопки — с `inset`-тенями как в `src/app/src/app.css`.
2. **Тексты — только через объект `T`** (EN и RU одновременно), никаких
   захардкоженных строк в разметке.
3. Не принимай токен через URL на этой странице: cookie выдаёт сам
   `/api/login`.
4. После правки — прогнать e2e: `BASE=… E2E_ADMIN=admin E2E_PASSWORD=…
   node e2e/run.mjs login` (набор проверяет кот, readme, lang, reset-hint,
   неверные и верные креды).

## Известные упрощения

- Кот — статичный SVG, не GIF (n2 в схеме нарисован как «gif»): анимация
  добавляется заменой `CAT_SVG` на `<img>`/`<picture>` без изменений логики.
- Readme-блок — короткая статичная заглушка + ссылка; подтягивание живого
  README с GitHub (n1: «render it») — в бэклоге.
- Смена пароля — только ручная процедура (см. выше), UI-формы нет.
