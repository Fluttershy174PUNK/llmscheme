# EDITOR.md — визуальный редактор (scheme.html)

> **Для кого:** тех, кто хочет править схему кликом и перетаскиванием вместо
> CLI-команд. Пользуешься только CLI — пропусти.

---

## Что такое редактор?

`.llmscheme/<type>_scheme/scheme.html` — **самодостаточная single-file
веб-страница**, которая открывается в любом современном браузере (Firefox,
Chrome, Safari, Edge). Размер ~110–135 КБ. Внутри весь редактор: Svelte-рантайм,
шрифт, стили, данные схемы. Интернет и сервер не нужны.

Открой двойным кликом в файловом менеджере, или:

```bash
# macOS
open .llmscheme/logic_scheme/scheme.html

# Linux
xdg-open .llmscheme/logic_scheme/scheme.html

# Windows
start .llmscheme/logic_scheme/scheme.html
```

## Что видишь при открытии

Страница делится на три области:

```
┌─────────────────────────────────────────────┐
│ верхняя панель: добавить, undo/redo, save…  │
├──────────────┬────────────┬──────────────────┤
│              │            │                  │
│  холст       │  палитра   │   инспектор      │
│  (узлы,      │  (фигуры)  │   (правка        │
│  рёбра,      │            │   выбранного     │
│  зоны)       │            │   узла/ребра/    │
│              │            │   зоны)          │
│              │            │                  │
└──────────────┴────────────┴──────────────────┴──── статусбар
```

- **Верхняя панель**: добавить узел, добавить зону, undo/redo, сетка, магнит,
  удалить, сохранить, язык, справка (?);
- **Холст** (слева): схема — клик и перетаскивание;
- **Палитра** (в середине): шесть кнопок фигур (rect, square, circle, ellipse,
  diamond, table);
- **Инспектор** (справа): поля выбранного узла/ребра/зоны;
- **Статусбар** (снизу): текущий rev, dirty-флаг, tier, счётчики узлов/рёбер.

## Инспектор — три разные «формы»

Правая панель меняется от выбранного. Три **отдельные формы** — в v1 был баг,
когда правка узла показывала поля ребра, а правка ребра — поля узла. v2 держит
их строго раздельно.

### Выбран **узел**

Видишь: label, description, shape (выпадающий список), позицию (x, y), размер
(w, h), refs (по пути на строку) и — если shape `table` — редактируемую сетку
таблицы с кнопками +/- для колонок и строк.

### Выбрано **ребро**

Видишь: from (список всех узлов), to (список всех узлов), style (solid /
dashed), label.

### Выбрана **зона**

Видишь: label, description, позицию (x, y), размер (w, h) и позицию подписи
(top / center / bottom / left / right).

Три формы не пересекаются. Не те поля просто не показываются.

## Сохранение — четыре «tier'а»

Редактор сохраняет изменения четырьмя способами — *tier'ами*. Какой активен,
зависит от того, как открыт редактор:

| Tier | Когда работает | Что делает |
|---|---|---|
| **A** | Всегда (универсальный fallback) | Генерит команду для агента. Вставил в терминал — агент выполнил `block put` и закоммитил. |
| **B** | Chromium (Chrome, Edge, Brave) | Диалог «Сохранить как» пишет файлы напрямую. Агент не нужен. |
| **C** | Firefox (нет File System Access API) | Скачивает файл. Потом `block sync --from <файл>` коммитит. |
| **S** | Редактор отдаёт HTTP-сервис | Прямая запись на сервер. |

Tier A важнее всех: **работает всегда**, не зависит от браузера. Кнопка SAVE
редактора всегда показывает Tier A. Статусбар показывает активный tier.

### Tier A в деталях

При SAVE в Tier A редактор:

1. диффит изменения против загруженной версии;
2. генерит готовую команду:

   ```bash
   node <skill-dir>/cli/block.ts put - --rev 7 <<'EOF'
   {
     "format": "block-llm",
     "version": 1,
     ...
   }
   EOF
   # rev 7 -> 8
   # changes:
   # - node n1.label: "Login" -> "Login page"
   # - edge e1 added: n1 -> n2
   ```

3. копирует в буфер;
4. показывает тот же текст в статусбаре на случай, если буфер не сработал.

Вставляешь в терминал, агент подхватывает, выполняет `block put` — изменение
закоммичено. При следующей загрузке редактор покажет новое состояние.

## Сетка и магнит

На холсте по умолчанию слабая сетка. Два тумблера в верхней панели:

- **Grid** — показать/скрыть линии сетки;
- **Snap** — примагничивать узлы к сетке при перетаскивании.

Шаг сетки — 20 пикселей. Магнит делает позиции аккуратными, но может мешать —
выключи для точного размещения.

Обе настройки хранятся в `localStorage` на браузер, так что переживают сессии.

## Статусбар — что значат числа

Снизу, слева направо:

- `rev N` — текущая ревизия;
- `(on disk M)` — ревизия, сохранённая на диске;
- `nodes X` — узлов в схеме;
- `edges Y` — рёбер;
- `zones Z` — зон;
- `tier A/B/S` — активная стратегия сохранения;
- `unsaved` (красный) — есть незакоммиченные изменения;
- `saved` (зелёный) — диск совпадает с видом;
- `N orphan(s)` — N узлов без рёбер (предупреждение);
- `patch→project` — у скилл-входа есть команда «patch to project».

## Открытие и сохранение локального файла

У скилл-редактора (открытого с `file://`) рядом с SAVE две кнопки — на случай,
когда `scheme.json` пришёл извне (коллега прислал) или нужен бэкап перед большой
правкой:

- **open local** — файловый пикер. Загружает любой `scheme.json` (нужен
  `"format": "block-llm"`) как текущую схему. Дальше правь и SAVE как обычно
  (Tier A даёт команду `put`, Tier B пишет файлы);
- **export** — скачивает текущую схему как `<name>.json`, без вопросов. Обычный
  `<a download>` — работает везде, включая Firefox.

Обе — простые браузерные примитивы (`<input type=file>` + `<a download>`),
работают офлайн с `file://` без File System Access API.

Серверный редактор этих кнопок не показывает (там схемы на сервере, не в
файловой системе).

## Браузерные особенности (конкретно Firefox)

Firefox не реализует File System Access API, поэтому:

- Tier B не работает (нет диалога «Сохранить как»). Редактор автоматически
  откатывается на Tier A;
- открытие `file://` с неопределённым `showSaveFilePicker` значит, что редактор
  использует простой «blob download» (Tier C) для черновика. Черновик живёт в
  `localStorage` и восстанавливается при следующем открытии.

Это намеренно. Tier A — универсальный fallback.

## FAQ

### «Жму SAVE — ничего не происходит»

Tier A копирует команду в буфер. Если буфер не записывается (ограничивающие
браузеры или нет разрешения), редактор показывает тот же текст в статусбаре
снизу. Скопируй оттуда и вставь в терминал.

### «Холст пустой, но в схеме есть узлы»

Узлы могут быть за экраном. Жми `fit` в панели (если есть) или отзумируй колёсом,
пока не появятся.

### «Нажал Ctrl+S — диалог про JSON-файл»

Ты в Tier B (Chromium). Браузер хочет сохранить состояние в файл. Выбери место —
файл будет `scheme.json`. Положи в каталог схемы проекта и выполни `block sync`
(или просто закрой редактор — CLI подхватит в следующий раз).

### «Есть несохранённые изменения, а надо закрыть вкладку»

Редактор покажет браузерный диалог (`beforeunload`) с подтверждением. Жми
«Покинуть», чтобы закрыть. Tier A всегда даёт команду для вставки до этого
(смотри статусбар снизу — команда там же).
